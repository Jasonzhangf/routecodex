2026-10-05T09:40Z / R48 namespace碰撞根因与修复｜RESOLVED(候选级), SUPERSEDES 08:35Z 条目。
上一条"剩余失败=provider-form未改写"的诊断错误，已作废；正确根因与修复如下。

正确根因：R43 与 PR343 对"命名空间 wire 缩短"有两套实现(重复实现)，且发射时序不一致。
- PR343：唯一 owner = 别名分配器 `openai_chat_namespace_wire_names`(按未哈希provider名分配,
  key=未哈希名)；`project_openai_chat_namespace_wire_names` 在 wire 上按名改写 tools/history/tool_choice。
- R43：在 `build_provider_function_tool` 内对 openai-chat 直接 sha256 哈希发射；分配器 key(未哈希)
  与发射值(哈希)不匹配 → 别名不生效；碰撞时 `sha256(ns__TOOL)==裸工具名` → 重复声明 → 502/400。
- 第二重不一致：R43 的 typed attempt map(`StandardOutboundDeclarationObserver.note_emitted`)在发射点
  记录名字，而别名改写发生在发射之后 → attempt map 与最终 wire 名字不一致 → 反投影丢 namespace。

修复(收敛为单一 owner + 时序一致，4 处)：
1. `provider-compat-core/src/namespace_tools.rs`：别名 key 改为发射态 wire 名(`aliases.insert(base, alias)`),
   保留 R43 发射哈希(strict_chat 不允许 >64 名，不可撤销)。
2. `hub_v1/request_outbound_builtin_tool_projection.rs`：在声明发射点(唯一选名处)解析别名，
   `apply_namespace_wire_alias` 于 `note_emitted` 之前写入 → wire 声明 = attempt map = history/tool_choice。
3. `hub_v1/request_outbound_mcp_names.rs`：`openai_chat_namespace_wire_aliases` 同时发布
   provider 逻辑名→alias 与 wire 哈希名→alias 两个 key；`project_openai_chat_namespace_wire_names`
   删除 tools 改写(已由发射点拥有)，只保留 history/tool_choice，避免把恰好等于哈希名的裸工具误改名。
4. `hub_v1/request_outbound_declaration_emission.rs`(Direct)：同一模式；`namespace_names` 解析为
   最终 wire 名(alias)，发射点同源改写。
