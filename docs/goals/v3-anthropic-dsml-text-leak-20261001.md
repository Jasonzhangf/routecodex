# Anthropic text control frame in Responses output

## Scope and evidence

The 4444 sample `openai-responses-router-gpt-5.5-20261001T034157121-589863-5791` has an Anthropic SSE `text_delta` stream whose joined text starts with `<thinking>` and ends with `</｜DSML｜parameter>\n</｜DSML｜invoke>\n</｜DSML｜tool_calls>`. Its final provider attempt was `goaichat:key1:deepseek-v4.1-flash` (HTTP 200); the preceding `xmcc2:key1:kimi-k3` attempt timed out on response headers. The other affected request, `openai-responses-router-gpt-5.5-20261001T033621995-589753-5681`, first received 429 from `goaichat_model:key1:deepseek-v4.1-flash` and then received the bad text plus separate native `tool_use` from `goaichat:key1:deepseek-v4.1-flash`. These bindings come from request-ID-matched 4444 logs/request records, not model-name inference.

The first sample directory contained `provider-response.json` but no `response.json`; therefore its exact client bytes are **unverified**. Separately, the screenshot's exact opening text appears in the later 4444 client request `openai-responses-router-gpt-5.5-20261001T041033163-590449-6377` at `input[554]` as `role=assistant`, `content[0].type=output_text`. This establishes that a control-tag block entered client-visible assistant history, but does not bind that history item to the first provider attempt.

The provider supplied the tags as text, not native Anthropic `tool_use`. This is an upstream malformed text frame. The proxy must preserve the raw provider response for diagnostics while preventing a proven control frame from becoming client-visible answer text. A native `tool_use` remains a native tool call; text is never promoted into one. The historical raw files were removed by sample retention after inspection; the paths and extracted shapes are evidence, but the full historical bytes are no longer available.

A controlled local HTTP replay now binds the same shape end to end. `responses_relay_anthropic_dsml_control_frame_is_not_client_output_text` starts a local Anthropic SSE mock, posts to the real `/v1/responses` entry, and receives HTTP 200 whose `response.output_item.done`, `response.completed`, and `response.done` all contain the full `<thinking>...DSML` text as `output_text`. The test fails its no-leak assertion on unmodified product code. See `v3-anthropic-dsml-red-replay.log`; this controlled fixture is a shape reproduction, not the lost historical raw response.

## Single-entry, single-exit response DAG

`Provider SSE raw (Anthropic text_delta/tool_use)` → `ProviderRespCompat02 materialization` → `RespInbound02 canonical Responses output + typed source-protocol witness` → `Resp03 Chat Process semantic classification` → either `valid native tool response / visible text → Resp05/Responses SSE projection → client`, or `invalid provider semantic response → typed provider-attempt failure → existing bounded Error-chain reselection → next candidate or true terminal error`.

The current first divergence is before Resp03: `responses_relay_runtime_inner.rs` derives `hook_provider_protocol=Responses` from an Anthropic SSE provider at lines 1052–1056, then `run_json_response_hooks` constructs its raw context using that normalized value. A proposed fix carries **both** typed values: canonical `provider_protocol` (kept as Responses for the existing hook behavior) and `source_provider_protocol` (actual `provider_wire_protocol=Anthropic`). Only the `V3ProviderRespInbound01RawContext` construction reads the source witness for already-materialized SSE; JSON Anthropic remains on its existing path because its RespInbound02 projection semantics differ. Existing consumers of canonical `provider_protocol` in `responses_relay_json_hooks.rs` are normalization, Responses MCP identity restoration, and OpenAI Chat conversion, and must retain their current meaning. Genuine Responses source remains Responses on both fields. Neither witness is put in a business payload or metadata. This is typed plumbing for the existing Resp03 owner, not a second filter.

The raw provider branch remains diagnostic only. Resp03 is the sole Relay semantic owner. The SSE tree and Anthropic codec parse and map the wire shape; they do not decide whether text is a control frame. Client SSE framing does not filter text. Direct mode uses its registered response hook and is outside this first fix unless the same recorded shape proves that path affected.

## Proposed classification contract

Apply classification only when the raw provider protocol is Anthropic, RespInbound02 has produced a canonical Responses assistant output, and Relay Resp03 owns the response. There are two disjoint top-level assistant text shapes: **A, DSML control frame** starts exactly with `<thinking>` and contains a DSML control delimiter; **B, paired thinking prose** starts exactly with `<thinking>`, has a complete `</thinking>` before nonempty visible prose, and contains no DSML delimiter. Quoted examples with a leading quote, code fences, ordinary text with a tag in the middle, user/request history, and native `tool_use` are outside both recognizers and remain unchanged. The raw capture remains unchanged.

For shape A, the observed complete frame ends with the three exact DSML closing lines after optional trailing whitespace. It carries no valid opening invocation, tool name, call ID, or arguments. Therefore it cannot itself authorize a synthesized tool call. A text-only DSML invocation may be recovered as a tool call only if a declared grammar proves a complete name, call ID, arguments, and terminator; the two observed samples supply no such grammar or complete fields, so this task does not invent that decoder. If separate native `tool_use` items make the response semantically valid, keep those native calls and omit only the complete control-frame text item from visible output. If shape A is incomplete or if removing its complete frame leaves no visible answer or native call, return a typed provider-response compatibility failure from Resp03.

For shape B, a complete `<thinking>...</thinking>` pair followed by nonempty ordinary prose has an unambiguous visible answer: remove only the paired internal segment and preserve the following prose unchanged. A lone paired internal segment with no visible prose or native call enters the same typed failure path. All other text remains unchanged. Typed failure enters the existing provider-attempt Error chain, where an eligible next candidate may run under the bounded selection policy. Client 502 is a true exhausted terminal result only; no malformed tags are committed to the client during an unsuccessful attempt.

No generic text cleanup, hidden reasoning projection, retry loop, or routing change is introduced. The classifier is deliberately narrow: ambiguous text outside the exact observed grammar is not silently rewritten. The current red fixture proves text-only corruption; separate native-call and two-provider fixtures must prove the recovery and retry branches.

An assistant can deliberately answer with a literal string identical to the entire malformed provider frame. Source, role, and bytes alone cannot distinguish that case; this rule has an irreducible ambiguity for that exact whole-item literal. It is intentionally narrower than blanket tag stripping, and the negative tests guard the common quoted/fenced forms. Any stronger claim requires extra upstream structure or a changed protocol contract.

This is a narrow compatibility rule for the observed upstream shape, not generic HTML/XML sanitation. Further shapes require their own bound samples and review.
