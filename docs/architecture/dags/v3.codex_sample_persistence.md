# Codex 样本持久化

```mermaid
flowchart LR
  A[接收诊断样本] --> B[按采样授权判断是否保存]
  B --> C[按字节预算接纳保存任务]
  C --> D[原样保存证据并执行保留策略]
  D --> E[返回保存或跳过或显式失败结果]
```

```mermaid
stateDiagram-v2
  [*] --> 待判定
  待判定 --> 已跳过: 未授权或仅保存错误或排除状态
  待判定 --> 已接纳: 有效样本且队列预算足够
  待判定 --> 已失败: worker缺失或预算耗尽
  已接纳 --> 已保存: 写入并刷新成功
  已接纳 --> 已失败: 文件系统失败
  已接纳 --> 已保存: 关闭时排空已接纳任务
  已跳过 --> [*]
  已保存 --> [*]
  已失败 --> [*]
```

图文件描述从 `enqueue_persist` 进入的单个异步诊断样本对象流；跳过或拒绝作为 typed 结果抵达唯一出口，不触发后续队列或文件系统 effect，无业务 payload 修改。拓扑不新增生产 DAGpipe 调度。唯一 owner 为 Debug crate 的 `V3CodexSampleStore`。这是非代理流水线功能图，放在 `docs/architecture/dags/`，由 `verify:v3-dagpipe-feature-graphs` 校验拓扑及真实资源 owner，不登记到代理流水线的 `modules.json`。

| 语义节点 | 实现边界 | 验收 |
| --- | --- | --- |
| 判断是否保存并接纳任务 | `V3CodexSampleStore::enqueue_persist`；内部与 `persist` 共用 `should_persist` | 未授权、普通样本及排除状态不占队列；force 502 不被跳过；64MiB预算同时计入序列化payload与每任务固定开销，额度耗尽显式记录且不影响业务请求 |
| 排空已接纳任务 | `run_v3_codex_sample_persist_worker` | 消费唯一队列，关闭时排空已接纳任务并释放字节预算 |
| 原样保存证据 | `V3CodexSampleStore::persist` / retention | JSON语义不变、保留provider attempts、0700/0600、写入错误显式；保存与启动保留策略共用进程间文件锁 |

图的队列字节预算属于 `v3.debug.codex_sample_persist_queue`，不读取表达诊断 payload 保真策略的 `v3.debug.payload_budget`。上游 snapshot 授权在创建样本任务前判断；本图不把它声明成存储 owner 的资源读取。入队或写入失败仍通过既有 `record_v3_codex_sample_persist_failure` owner 进入有界 failure ledger；它是节点内部错误终点，不新增代理 Error 链或成功包装。

范围：Debug persistence owner及公开接口回归；不改Provider、Router、SSE或客户端协议。成功/跳过/失败终点均以样本文件或failure ledger可核验；关闭排空已接纳任务。真实HTTP成功/失败入口验收由Server已有黑盒harness及安装后4444/7777验证完成。

共享采样文件系统由 Debug 独占协调：在样本根目录的固定 `.retention.lock` 上取得标准库文件锁后，才创建、读取、写入或清理请求目录。根目录的创建仅用于引导锁文件；锁文件不进入请求保留计数，不被清理。持锁 File 在成功或错误返回时释放。启动 `enforce_listener_retention` 与写入 `persist` 使用同一个锁 owner；单 store 的 Mutex 已移除。真实锁和文件错误继续显式返回。

黑盒命令为 `npm run test:v3-shared-sample-retention-blackbox`。稳定用例 `shared_sample_retention_parallel_cli_startup_blackbox` 从公开 CLI 与 HTTP 验证共享 HOME 的六个独立实例并发启动、真实外部 provider 响应、原样样本和全局保留上限；`shared_sample_retention_invalid_lock_is_explicit_blackbox` 从 CLI 验证无效锁文件错误。两者进入 canonical CLI CI。原 H2 并发级别与断言保持不变。
