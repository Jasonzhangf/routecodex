# No-fallback source-scope gate

This graph documents the existing standalone CI command, not a new production
operator or a runtime registry entry. Its sole node is the existing source scan
owned by `scripts/architecture/verify-no-fallback-diff.mjs`, called by
`npm run verify:no-fallback-all`. The configuration input is
`docs/architecture/no-fallback-diff-rules.json`. The exit is the command verdict:
zero for no rule violations, nonzero plus file/line diagnostics for violations
or missing input. CI command cancellation remains CI cancellation; the scanner
has no daemon, persistence, retry or shared-resource lifecycle.

Bug812a528 corrects the declared scan scope for the existing
`routecodex-v3-lifecycle/src/hooks_sidecar/tests.rs`, which is included only by
`#[cfg(test)] mod tests` in `hooks_sidecar.rs`. This exact test-only path follows
the existing exclusions for test directories. No broad Rust filename exclusion,
line-text allowlist, rule change or runtime behavior change is introduced.
Production `hooks_sidecar.rs` and neighboring source remain subject to every
rule. The black-box command regression executes the real scanner with a
temporary repository-shaped input and the actual scope configuration. It checks
the test assertion succeeds, production fallback/degrade violations fail, a
neighboring source violation fails, and fixture cleanup completes. The existing
`verify:fallback-hardcode` command owns this regression and both existing gates.
