## L94-custom-tool-call-input-sse-events-not-provider-failure
- Trigger: live `/v1/responses` Relay fails with `response.custom_tool_call_input.delta is unsupported`, then VR switches/retries provider.
- Judgment: `response.custom_tool_call_input.delta/.done` are official OpenAI Responses events (openai-openapi spec) streaming the `input` of `custom_tool_call` output items; protocol truth, not provider failure. Same class as L93-reasoning-summary.
- Action: materialize at `responses_provider_event_codec.rs` (resp-side inbound provider-wire codec): `.delta` appends `delta` to matched item `input`, `.done` sets `input`; reuse `find_v3_runtime_responses_event_function_item_mut`.
- Anti-pattern: treating upstream custom tool events as provider health failure, fixing Error06 display, patching VR/provider config, or leaking Responses req fields into provider request.
- Boundary: unknown `response.*` events still hard-fail; no silent ignore.
- Evidence: red test with exact live error first, green after; live replay on installed binary (asxs gateway family with custom apply_patch tool) HTTP 201 with correct `custom_tool_call.input`.
