# protocol-live-mock-matrix

Fixed corpus for the live RCC HTTP baseline matrix. It feeds the E1/E4 runner
whose interface is published at
`/Volumes/Intel/playground/routecodex/.worker-runs/magpie-live-matrix-20261012-0435/runner/interface.md`.
The runner owns the RCC instance, the loopback mock upstream, capture, and
assertion execution. This directory owns only the fixed inputs, provider wire
fixture, and independently written expected values.

## Scope

- 16 cells: four entry protocols (`openai_chat`, `responses`, `anthropic`,
  `gemini`) x four provider protocols.
- Same-protocol cells use the default Direct path. Cross-protocol cells use
  Relay. One same-protocol cell is duplicated as an explicit Relay case.
- `manifest.json` lists case files; each case carries `cell.transport` and
  `upstream_response.mode` for JSON/SSE and provider fault scripts.
- Boundary cases A-F cover tool/namespace follow-up, media, reasoning
  signatures, usage/terminal state, provider error exhaustion, and unregistered
  field continuation/no control leakage.

## Expected-value policy

Expected values are written from current RCC requirements v6, the current
request field whitelist, the four protocol shapes, and the fixed Magpie source
inputs. They are never generated by RCC or Magpie codecs. Dynamic provider
values (message ids, response ids, timestamps) are allowed only where the
protocol requires them; cases that need them state the policy in
  `assertions`.

Provider HTTP/error-channel failures stay internal. Exhaustion closes the
client request; it never returns a proxy-generated error, HTTP error status,
SSE error payload, or fabricated success.

## Source provenance

- Repository: `https://github.com/yetone/magpie`
- Development reference clone used for extraction: `/Volumes/extension/code/magpie`
- SHA: `bfaedf18301d02a423bd5422d22e41432d231ab8`
- License: MIT (`LICENSE.magpie`)

The clone path records the original development reference. Local mock, corpus
and manual matrix use read this repository's fixtures and do not require that
clone or fetch Magpie. Optional source auditing requires an explicitly supplied
reference root. Routine CI does not execute this reference-tool suite.

Magpie is an input and shape reference. Its own golden expectations are not
ported wholesale. In particular, current RCC requirements reject synthesized
tool results, generic argument wrapping, system/developer user-reminder
rewriting, dynamic optional-field deletion, guessed signatures, implicit
permission grants, client-visible provider errors, and error-returning
exhaustion. Cases that touch those behaviors record the difference in
`contract_difference` or `independent_expected_note`.
